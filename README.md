# multiplayer-kit

[![CI](https://github.com/Oleg4311/multiplayer-kit/actions/workflows/ci.yml/badge.svg)](https://github.com/Oleg4311/multiplayer-kit/actions/workflows/ci.yml)
[Релизы](https://github.com/Oleg4311/multiplayer-kit/releases)

**Комнаты для сетевых игр на Cloudflare Durable Objects и WebSocket, где сервер решает всё.** Игра описывается чистыми функциями (`init`, `parseAction`, `apply`, `view`), а комнаты, места, переподключение, проверка ходов и рассылка «каждому своего вида» уже сделаны. В демо два игры: **морской бой** (скрытая информация: расстановку соперника сервер не показывает до конца партии) и **четыре в ряд**.

**Играть:** https://multiplayer-kit.olegbelii4311.workers.dev/ (создайте комнату, отправьте код другу) · [English](#english)

## Как это работает

```
браузер ──WebSocket──► Worker ──► Durable Object «Комната» (одна на код)
   hello / start / act            │  проверка ввода, правила игры, журнал действий
   ◄── state: ваш вид ────────────┘  рассылка: каждому сокету его собственный вид
```

- **Клиент присылает намерение, сервер решает.** Клиент не знает чужих секретов и не может сделать недопустимый ход: `apply` бросает `GameError`, состояние при этом не меняется ни на байт (проверено тестом).
- **Скрытая информация не покидает сервер.** `view(state, seat)` строит то, что видит игрок на данном месте. В морском бое это: ваши корабли, результаты выстрелов по обеим доскам и корабли, потопленные целиком. Чужая расстановка открывается только после конца партии.
- **Переподключение.** При входе сервер выдаёт секретный токен места (хранится только его SHA-256). Закрыли вкладку, обновили страницу, пропала сеть: клиент входит по токену на то же место, партия продолжается.
- **Гибернация.** Комната на WebSocket Hibernation API: пока никто не ходит, объект не держит память и не тарифицируется как работающий. Состояние лежит в хранилище Durable Object, а не в памяти.
- **Воспроизводимость.** Вся случайность идёт через зерно комнаты и номер действия. Журнал действий плюс зерно восстанавливают партию в точности (тест сверяет это на 40 партиях).
- **Зрители.** Вход с `spectate` даёт вид без личных данных; ходить зритель не может.
- **Ограничения.** Размер сообщения до 2 КБ, 8 сообщений в секунду на соединение (при систематическом превышении соединение закрывается), до 12 соединений в комнате, проверка `Origin` для запросов из браузера, срок жизни комнаты сутки после последнего действия (Durable Object alarm).

## Как добавить свою игру

```ts
import type { GameDef } from './kit/types.ts';

export const myGame: GameDef<State, Action, View> = {
  id: 'my-game', title: 'Моя игра', minPlayers: 2, maxPlayers: 4,
  init: (players, rng) => ({ /* начальное состояние (JSON) */ }),
  parseAction: (raw) => { /* проверить непроверенный ввод, бросить GameError */ },
  apply: (state, action, seat, rng) => { /* вернуть новое состояние или бросить GameError */ },
  view: (state, seat) => ({ /* только то, что видит это место; seat === null у зрителя */ }),
  outcome: (state) => ({ over: false }),
  turn: (state) => 0,
};
```

Добавьте игру в `src/games/index.ts`: комнаты, WebSocket, переподключение и рассылка заработают без правок сервера. Так же сделан «Четыре в ряд» (≈100 строк).

## Что проверено

- **Скрытая информация, три слоя.** (1) Чистая игра: по виду игрока на каждом шаге 60 случайных партий проверяется, что в нём нет клеток чужих кораблей, по которым не стреляли; метаморфный тест: две партии, различающиеся только расстановкой соперника, дают игроку одинаковые виды, пока нет попаданий. (2) По сети: настоящий собранный Worker в Miniflare, два WebSocket-клиента играют партию до победы, и **каждый сырой кадр** анализируется на утечки; токены не попадают в чужие кадры. (3) В браузере: на поле соперника до конца партии нет ни одной клетки с меткой «корабль».
- **Мутации.** Если `view` начинает отдавать расстановку до конца партии, падают четыре теста на трёх слоях (проверено вручную); сама проверка утечки проверена на заведомо «дырявом» виде.
- **Правила.** Все отказы морского боя (выход за поле, пересечение, повторная расстановка, чужой ход, повторный выстрел, ход в чужой фазе); 200 случайных партий заканчиваются победой того, кто потопил весь флот; «Четыре в ряд» сверен с независимым перебором на 500 партиях.
- **Комната.** Токены хранятся хешами; имя нормализуется (пробелы, управляющие и невидимые символы, направленность текста); дубликаты; старт только у создателя; журнал воспроизводит состояние; ошибка не меняет комнату.
- **Сервер.** Чужая страница получает 403, мусорные и слишком длинные сообщения, ограничение частоты, закрытие при перебое, закрытие комнаты по сроку (в тесте срок сокращён до 1,5 секунды), переподключение, зрители, опоздавшие.
- **Интерфейс.** Две вкладки играют по-настоящему; перезагрузка возвращает на место; axe без серьёзных нарушений; нет горизонтальной прокрутки; десктоп и телефон. После каждого деплоя CI прогоняет те же сценарии на живом адресе.
- 37 тестов (`node:test`), 14 сценариев Playwright (7 на десктопе и 7 на телефоне), `tsc --strict`.

## Честные ограничения

- **Сервер видит всё.** Имена, расстановки и ходы лежат на сервере в открытом виде (в хранилище Cloudflare), это доверие к хозяину сервера, а не сквозное шифрование. Скрытая информация скрыта от соперников, не от оператора.
- **Токен места на устройстве не шифруется.** Кто получил доступ к браузеру игрока, может войти на его место. Потерянный токен восстановить нельзя.
- **Лимиты по соединению, а не по IP.** Создавать комнаты можно без ограничений: от злоупотреблений защитят правила Cloudflare (rate limiting), в проект они не входят. Комнаты удаляются сами через сутки.
- **Гибернацию в тестах не воспроизвести.** Miniflare не усыпляет объект, поэтому тесты подтверждают, что состояние читается из хранилища (переподключение после закрытия соединений), но не саму выгрузку из памяти. Правильность держится на том, что в памяти объекта нет ничего, кроме счётчика частоты.
- **Нет ничьей по тайм-ауту, нет «сдаться», нет рейтингов.** Если соперник ушёл, партия ждёт его до закрытия комнаты.
- **Расстановка кораблей случайная** (кнопка «Другая расстановка»): ручная расстановка не сделана.
- **Две игры на двоих.** Ядро допускает больше мест (`maxPlayers`), но демо этого не показывает.

## Разработка

```
npm install
npm test            # правила, комната, настоящий Worker в Miniflare (нужен Node 24)
npm run typecheck
npm run build       # страница в site/
npm run e2e         # сценарии в браузере (один раз: npx playwright install chromium); локальный сервер поднимется сам
npm run serve       # страница и API на http://127.0.0.1:4176/
```

Деплой идёт из CI (`wrangler deploy`, секреты репозитория `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`). Если на машине настроен прокси, для локальных запусков добавьте `NO_PROXY=127.0.0.1,localhost`.

## English

**multiplayer-kit** is a small framework for authoritative-server multiplayer games on Cloudflare Durable Objects with hibernating WebSockets. A game is four pure functions (`init`, `parseAction`, `apply`, `view`); rooms, seats, token-based reconnection, move validation, an action log with seeded randomness and per-player views come for free. The demo ships **Battleship** (hidden information: the opponent's fleet never leaves the server until the game ends) and **Connect Four** — no server changes needed to add a game.

Verified at three layers: pure game logic (property and metamorphic tests of the per-player view), the real built Worker under Miniflare with two WebSocket clients where every raw frame is scanned for leaks, and two browser tabs playing a full game in Playwright (also against the live deployment after each deploy). A deliberate leak in `view` makes four tests fail. Honest limits: the server operator can see everything (no end-to-end encryption), rate limits are per connection rather than per IP, hibernation itself cannot be exercised in Miniflare, no resign/timeouts, random fleet placement only. MIT licensed. Built with Claude.
